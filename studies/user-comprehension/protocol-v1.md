# Frozen user-comprehension protocol

This protocol qualifies the immutable simulated public demo against the Milestone 6 comprehension gate.
The machine-readable authority is `protocol-v1.json` and the run-record contract is `result.schema.v1.json`.

## Cohort

Recruit exactly five participants for each run.
Every participant must be a first-time RateReplay user, must not have read implementation documentation, and must not have taken part in an earlier run.
Do not collect names, contact details, utility data, account data, or other identifying information.
Use only the opaque participant identifiers generated by the study initializer.

If a run fails, retain its complete record.
Revise the explanation design, create the next numbered run, and recruit five fresh first-time participants.
Never remove or replace a failed participant within a run.

## Environment preparation

Use a clean checkout of the commit recorded in the run document.
Run the following commands before a participant begins:

```sh
make bootstrap
make demo-artifacts-check
corepack pnpm build
corepack pnpm --filter @ratereplay/web exec vite preview --host 127.0.0.1 --port 4173
```

Open `http://127.0.0.1:4173/#demo` in a clean browser context.
Do not open implementation documentation or private-account screens for the participant.

Create the first run record in a separate terminal:

```sh
UV_CACHE_DIR=/private/tmp/rate-replay-uv-cache uv run python scripts/user_comprehension_study.py init \
  --attempt 1 \
  --git-commit "$(git rev-parse HEAD)" \
  --demo-url http://127.0.0.1:4173/#demo \
  --browser-name BROWSER_NAME \
  --browser-version BROWSER_VERSION \
  --output evidence/user-study/m6-comprehension-v1-run-01.json
```

The initializer creates five random opaque participant identifiers and deliberately incomplete observations.
It refuses to overwrite an existing run record.

## Facilitator script

Read only the following introduction before starting:

> This is a simulated historical electricity-rate walkthrough.
> Starting on the public demo, review each step through the redacted report as if you were deciding what the result means.
> Think aloud if you are comfortable doing so.
> I cannot explain the interface or answer questions while you work, but I can repeat the task instruction.

Give the participant the workflow instructions from `protocol-v1.json` one at a time.
Do not point at controls, define application terms, interpret a result, confirm an answer, or reveal the answer rubric.
Repeating the exact current instruction is permitted and is not coaching.
Record whether each step was completed independently and record every wrong turn using a short anonymized description.
Record the total duration in seconds.

After the participant reaches the redacted report, ask the five question prompts from `protocol-v1.json` verbatim and in their listed order.
Do not show the answer options.
After the participant answers, write a short anonymized paraphrase and assign the closest answer identifier from the frozen rubric.
Use `UNKNOWN_OR_OTHER` when a response is absent, materially incomplete, or does not fit a listed incorrect answer.

Record content-focused observations only.
Do not record a participant's name, employer, demographic information, utility, address, bill amount, account identifier, or other personal or source data.

## Scoring and qualification

A participant succeeds only when every workflow step was completed independently and all five coded answers match the accepted answer identifiers.
Wrong turns do not by themselves fail a participant when the workflow was still completed independently.
The run passes only when at least four of the five participants succeed.

Set every run-level attestation to `true` only after verifying that it is accurate.
Then run:

```sh
make qualification-m6-study
```

The validator checks the protocol and demo hashes, exact cohort and question coverage, uncoached first-time-user attestations, derived participant scores, four-of-five threshold, retry chain, preservation of failed runs, and freshness of opaque participant identifiers across runs.
A missing, incomplete, failed, selectively reported, or stale run returns a nonzero status and does not satisfy the milestone gate.
